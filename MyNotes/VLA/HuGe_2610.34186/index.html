    HuGe: Scaling Humanoid Generalist Vision-Language-Action Models with Egocentric Experience¶

    研究问题¶

    [论文原文] 人类第一视角示范规模较大，但视觉形体与机器人不同，且缺少机器人本体状态；G1 全身遥操作数据则昂贵。论文要验证：人类第一视角数据能否经统一动作表示、伪本体状态和视觉适配，帮助人形机器人完成全身任务（PDF 第 1、3–5 页，第 1、3 节）。

    核心方法¶

    [论文原文] 三阶段：① 第一视角预训练，混合 EgoDex、EgoVerse、Xperience-10M 和模拟 BEHAVIOR-1K，共 1,669.61 小时；② 用真实 G1 示范适配，共 417.58 小时；③ 在 HumanoidArena 或真实可乐拾取投放任务上微调。数字来自 PDF 第 4 页表 1。这里的第一阶段不全是人类视频，BEHAVIOR-1K 是模拟机器人数据。

    作者把已有 OFT、GR00T、π 风格 VLA 迁移到同一 SONIC 动作接口，而非提出新的 VLA 主干。每步动作是 64 维 SONIC 运动 token 加 2 个二值手部信号。第二项创新是将人类动作在模拟 G1 上回放，重建 34 维伪本体状态；第三项是对下游人类视频去除人手臂、补景并合成机器人手。出处：PDF 第 3–5 页图 1 与第 3.1–3.2 节。[独立判断] 方法贡献主要是跨形体数据对齐和训练配方，不宜称为新骨干架构。

    实验与局限¶

    [论文原文] HumanoidArena 有 7 项任务，每项 100 条示范，评估每项 60 次（3 组、每组 20 次）。表 4 的总体平均成功率：HuGe-GR00T 66.67%、HuGe-Pi 65.00%、HuGe-OFT 54.05%，最强列示基线 π0.5 为 53.81%。部分基线标 †，来自原 HumanoidArena 论文，不是全部由 HuGe 作者在同一运行中复测（PDF 第 5、7 页，第 4.1 节与表 4）。

    [论文原文] 伪本体状态消融：GR00T 从 61.67% 提升至 66.67%（+5.00 个百分点），Pi 从 62.14% 至 65.00%（+2.86），OFT 从 56.43% 降到 54.05%（−2.38）；作者将 OFT 下降与把状态序列化成文本后发生截断联系起来（PDF 第 6 页，表 3）。因此“伪状态总是有益”不受实验支持。

    [论文原文] 真实 G1 可乐任务每组 30 次：仅 110 条机器人示范成功 13/30（43.3%）；加入 400 条原始第一视角示范为 18/30（60.0%）；改用视觉适配示范为 20/30（66.7%）。这些是单任务、小样本结果，不能外推为普遍真实机器人成功率；瓶颈包括抓取失败与抓取时平衡不稳（PDF 第 7–9 页，图 3 与第 4.2 节）。

    整体系统与网络架构¶

    [论文原文] 输入为第一视角 RGB 图像、自然语言指令及 34 维本体状态；Qwen3-VL-2B-Instruct 作视觉语言骨干。OFT 风格用 MLP 并行预测动作块；GR00T 风格用骨干上下文特征经 cross-attention 条件化 DiT，以 flow matching 生成动作；Pi 风格用多层骨干隐藏状态逐层条件化 DiT。三者都输出 50 步、每步 66 维动作块，50 Hz 控制。SONIC 低层控制器固定，用 64 维 token 与当前机器人状态生成关节级控制；两维手信号单独控制开合（PDF 第 3–4 页，第 3.1 节；第 13–14 页附录 A–B）。

    [源码验证] 官方仓库提交 f9e1a54403b49a6f6a3f05ec36cf818ca769f381 已公开模型、数据、训练和服务端代码；下文只对实际读过的路径作源码结论。默认配置的动作头宽度 1024、层数 16、动作长度 50、维度 66，见 src/huge/models/qwen_sonicfm.py:279-320,430-503；这是该提交的默认值，不能自动等同于论文所有实验的实际检查点。SONIC 预训练模型、真实数据和实际部署延迟未随本次源码审阅验证。

    数学建模与核心公式推导¶

    34 维本体状态（附录 B，公式 1，PDF 第 14 页）¶

    [论文原文]

    \[ s_t = [(q_t^{body})^\top, h_t^L, h_t^R, (g_t^{body})^\top]^\top \in \mathbb{R}^{34} \]

    其中 \(q_t^{body}\in\mathbb{R}^{29}\) 是 G1 关节角（rad），\(h_t^L,h_t^R\in\{0,1\}\) 是手部开合（0 开、1 闭），\(g_t^{body}\in\mathbb{R}^{3}\) 是机体坐标系下单位重力方向（无量纲）；维数为 \(29+2+3=34\)。分量顺序见附录 B 表 6。[原理推导] 这使人类数据通过模拟回放得到机器人状态条件，但伪状态质量依赖回放及重定向误差。

    分位数裁剪与归一化（附录 B，公式 2，PDF 第 14 页）¶

    [论文原文]

    \[ \hat{s}_{t,i}=2\frac{\operatorname{clip}(s_{t,i},\ell_i,u_i)-\ell_i}{u_i-\ell_i+10^{-8}}-1 \]

    \(\ell_i,u_i\) 分别是第 \(i\) 维训练数据第 1、99 百分位边界，单位与该维状态相同；\(\hat{s}_{t,i}\) 无量纲。Stage 1、2、3 的统计分别基于迄今累积训练数据；推理复用随检查点保存的 Stage 3 统计。[原理推导] 令 \(x_i=\operatorname{clip}(s_{t,i},\ell_i,u_i)\)，则仿射映射把 \(x_i=\ell_i\) 送至 \(-1\)，把 \(x_i=u_i\) 送至 \(1-2\cdot10^{-8}/(u_i-\ell_i+10^{-8})\)，即略小于 1。区间内部对 \(s_{t,i}\) 的导数为 \(2/(u_i-\ell_i+10^{-8})\)，区间外为 0；边界处导数不唯一。\(10^{-8}\) 避免分母为零，但当 \(u_i\approx\ell_i\) 时仍需核查数值尺度。[源码验证] data/proprio_normalizer.py:ProprioNormalizer.normalize 实现逐维裁剪与该仿射映射；统计文件的实际数值仍待数据验证。

    核心算法与训练流程¶

    [论文原文] 第一阶段把异构人类/模拟数据转换为 SONIC token，模拟回放构造伪状态，训练条件动作块预测；第二阶段在真实 G1 示范上继续训练骨干与动作模块；第三阶段按任务混合机器人和人类示范微调。附录 A 表 5 报告 AdamW、BF16、余弦学习率、VLM 学习率 \(10^{-5}\)、动作头 \(10^{-4}\)、投影器 \(2.5\times10^{-5}\)。[源码验证] 当前 runner.py 有分组优化器和按阶段默认参数；仅有默认代码并不能证明论文实验恰按这些默认值运行，需检查发布的运行配置和检查点。

    训练图像：长边最多 512，补成方形并缩放至 \(256\times256\)；训练随机裁 \(243\times243\) 后回缩，推理改中心裁切且不做颜色扰动（PDF 第 13–14 页，附录 A）。[源码验证] 已静态核查数据采样、损失掩码与优化器分组的关键路径，详见后文；图像预处理和实际运行配置仍须逐项验证。

    推理与部署¶

    [论文原文] 部署输入应是实时 RGB、指令和真实 G1 本体状态；模型预测动作块，SONIC 将运动 token 转为关节级命令，手信号控制开合。训练的伪本体状态只是构造人类示范监督的手段，不应误写为机器人部署时可直接读取的观测。论文报告 50 Hz 动作时间线。[源码验证] 服务端缓存与按时间索引消费机制见后文；端到端推理延迟和实体机器人调度仍未实测。

    论文与源码一致性¶

    官方仓库：yliu-cs/HuGe，本次审阅固定在提交 f9e1a54403b49a6f6a3f05ec36cf818ca769f381。已逐段查看动作头、统一模型、损失、部分数据集、归一化、训练 runner 与服务端的关键函数，属于静态源码审阅，不等于模型权重、完整数据流水线或真实机器人运行验证。下节给出逐项证据和边界。

    算法级深化：SONIC 表示与跨形体接口¶

    [论文原文] HuGe 的单步输出为 64 维 SONIC motion token 加两维左右手开合标签；SONIC 的控制解码器以 token 和机器人本体状态生成全身关节控制，手部由独立信号处理（第 3.1 节，PDF 第 3–4 页）。64 维是潜在运动表示的维数，不是 64 个关节角，也不是 64 个离散词汇 ID。EgoDex 已提供 SONIC token；EgoVerse 将筛选后的头/腕轨迹与固定站立下肢参考编码；Xperience-10M 将全身运动参考转换为编码器所需输入；BEHAVIOR-1K 由 SONIC planner 根据上肢姿态、底座运动和高度参考生成 G1 运动（第 3.2.1 节）。这些路径不是同一个“人类动作直接喂给编码器”的流程。

    [源码验证] scripts/preprocess/xperience-10m/calc_sonic_tokens.py:_encode_payload 构造编码器输入并运行 SONIC ONNX encoder，检查输出形状；scripts/preprocess/calc_proprio/run.py 调用 SONIC 仿真回放和状态导出；src/huge/models/qwen_sonicfm.py:predict_action 在推理末端把前 64 维夹到 \([-1,15/16]\)，乘 16 后四舍五入再除 16，即逐维投影到 32 个标量级别。故原笔记“连续动作”只适用于动作头的回归/流生成中间值；最终下发的 motion token 位于量化网格。该 token 随时间构成序列，但“连续性”不能理解成每个 token 分量是任意实数，也没有证据证明相邻时刻必然光滑。手部两维在训练目标中以数值回归，sonic_adapter.py:HandHysteresis.update 再用 0.6/0.4 双阈值转为开合状态。

    [原理推导] 统一 token 接口把多来源运动标签映射到相同 64 维目标，使高层策略不必直接拟合各来源不同的关节坐标；固定低层控制器承担运动执行。但映射只统一动作监督形式，不自动消除相机视角、人体/机器人外观、伪状态偏差、接触动力学或真实 G1 执行误差。[待验证] SONIC encoder/decoder 的权重、输入语义和低层控制律未在本次审阅中运行验证；不可把 64 维逐轴解释为具体物理关节或将低层执行成功归功于 VLA 本身。

    算法级深化：三种 VLA 的一次 forward¶

    以下形状只表示已在代码中明确检查的接口；\(B\) 是 batch 大小，\(T=50\) 是默认动作长度，\(D=66\) 是每步动作维度，\(H=1024\) 是当前源码默认动作头宽度。Qwen 视觉 token 数与隐藏维取决于加载的骨干，不能凭配置默认值编造固定数值。

    分支 数据流与条件注入 训练输出/损失 推理
    OFT qwenoft [源码验证] HugeCollator 将 34 维归一化状态分箱为文本，接在任务文本后，再加 50 个动作占位 token；Qwen 最后层 [B,L,H_q] 经投影，按占位位置取 [B,T,H]；StarVLAOFTActionHead 的 MLPResNet 独立映射每个位置为 [B,T,66]。见 data/collator.py:append_oft_prompt,__call__、models/qwen_sonicfm.py:forward、models/action_heads/starvla_oft_head.py。 [源码验证] training/losses.py:qwen_sonicfm_loss 对有效维度做 masked MAE；不存在此分支的扩散/flow 迭代。 [源码验证] 一次前向并行输出 50 步，随后前 64 维被量化到 SONIC 网格。
    GR00T qwengr00t [源码验证] Qwen 最后一层上下文经投影给 SingleContextDiT 的 cross-attention；动作噪声/时间嵌入、可选状态 token 和 32 个未来 token 组成动作侧序列，默认 16 层、宽 1024。见 qwen_sonicfm.py:forward 与 starvla_gr00t_head.py:_build_sequence,forward。 [源码验证] 对 66 维动作做线性噪声插值，预测速度，losses.py 对有效维度计算 masked MSE。 [源码验证] 从高斯噪声出发，默认 4 次显式 Euler 更新，再量化前 64 维；不是一次直接回归。
    Pi qwenpi_v3 [源码验证] encode_vlm_layers 取多层 Qwen 隐状态，经逐层投影，分别进入 DiT 16 层的 cross-attention；动作侧含可选状态 token 与 [B,T,H] 动作 token。见 qwen_sonicfm.py:encode_vlm_layers,forward、starvla_pi_head.py:DiT.forward。 [源码验证] 与 GR00T 同属代码里的 velocity flow 训练，masked MSE；差异是逐层条件而非单一末层上下文。 [源码验证] 默认 4 步 Euler 生成 50 步动作，最后投影 SONIC 网格。

    [源码验证] training/losses.py 对 66 维统一使用 sonic_mask；手部两维没有单独 BCE 分类损失。流分支代码的实际构造为 \(x_t=(1-t)\epsilon+t a\)、\(v^*=a-\epsilon\)，\(a\in\mathbb{R}^{B\times T\times66}\)；这来自 starvla_gr00t_head.py:forward 和 starvla_pi_head.py:forward，是本仓库实现式，不是 HuGe 正文新提出的理论公式。损失是对有标签维度的 \((v_\theta-v^*)^2\) 求均值；OFT 则对 \(|\hat a-a|\) 求 masked 均值。训练的流插值目标与推理时有限步 Euler 离散化并非同一个误差来源。

    [论文原文] 表 4 的整体成功率依次为 OFT 54.05%、GR00T 66.67%、Pi 65.00%。[独立判断] 这说明当前数据和训练条件下两种 flow 动作头更强，但三分支同时改变了状态注入、VLM 特征使用和生成方式；单靠表 4 不能把性能差异归因于“flow matching 优于 MAE”。

    算法级深化：三阶段数据、时间对齐与参数更新¶

    [论文原文] Stage 1 的来源和小时数仍以表 1 为准；EgoDex 821.80 h、EgoVerse 47.08 h、Xperience-10M 478.33 h、BEHAVIOR-1K 322.40 h。人类运动经不同来源特定的重定向/参考格式进入 SONIC；BEHAVIOR 是模拟机器人。Stage 2 为 Humanoid Everyday 16.47 h、UniFoLM-WBT 22.96 h、HIW-500 378.15 h；分别利用 G1 SONIC 与真实状态、统一二值手标签、或由控制事件保持到下一次开合事件的手标签（第 3.2.1–3.2.2 节）。Stage 3 的 HumanoidArena 与真实可乐任务分别训练，不是将全部下游任务无条件混成一个模型（第 3.2.3 节）。

    [论文原文] Stage 1 将 token 在模拟 G1 上回放，记录 29 个关节角、两维手状态和机体系重力方向；BEHAVIOR-1K 在 planner 执行时记录配对数据。可得的动作标签用于手部状态代理，EgoDex 则保留模拟手状态；缺失的 EgoDex 手部动作标签不监督。应区分状态输入的两维手值与动作目标的两维手标签，二者不是同一变量（第 3.2.1 节、附录 B）。
