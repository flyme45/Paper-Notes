    Computational Barriers to Filtering for AI Alignment¶

    会议: ICLR2026
    OpenReview: https://openreview.net/forum?id=CwoM9T55lG
    代码: 待确认
    领域: AI 安全 / 对齐理论 / 密码学
    关键词: 安全过滤器, 越狱攻击, 时间锁谜题, 计算不可区分性, 不可能性结果

    一句话总结¶

    这篇论文用密码学证明：当安全过滤器的算力严格弱于被监管的 LLM 时，无论过滤输入 prompt 还是过滤输出，都存在「可证明无法被高效过滤器识别、却能可靠诱发 LLM 有害行为」的对抗 prompt，因此纯外部（黑盒）过滤无法保证对齐，监管必须触及模型权重内部。

    研究背景与动机¶

    领域现状：当下保证 LLM 不输出有害内容的主流工程手段是「外挂过滤器」——在 prompt 进模型前用一个输入过滤器（input filter）拦截危险请求，或在模型生成后用输出过滤器（output filter）拦截危险回答。Meta 的 Llama Guard、Google 的 ShieldGemma、Azure / Nvidia 的内容审核都属于这类外部防护，它们被部署在模型外侧，不需要访问模型内部权重。

    现有痛点：实践中这些过滤器不断被「越狱」（jailbreak）绕过——把有害请求用 Caesar 密码、Morse、ASCII 编码一下就能让护栏失效。但这些都是经验性的攻防你来我往，没人回答一个更根本的问题：这种绕过到底是工程没做好、还是有内在的、原理上无法消除的障碍？

    核心矛盾：作者抓住一个被忽视但极其真实的不对称——过滤器比 LLM 弱得多。现实里护栏模型都是轻量级的（最新的 Llama Guard 4 约 12B 参数），而被它守护的 GPT-5 / Gemini 大得多，因为给每个请求都套一个巨型护栏会带来无法接受的延迟和成本。于是「安全」永远只分到比「能力」少得多的算力。问题随之而来：用远少于 LLM 的算力，能不能在黑盒外侧把对齐做出来？

    本文目标：把这个工程直觉变成可证明的数学命题，分别回答三个子问题——（1）输入过滤可能吗？（2）输出过滤可能吗（即便允许过滤器比 LLM 还强）？（3）放宽到允许过滤器「修改」而非只「拒绝」prompt 的缓解（mitigation）过滤，可能吗？

    切入角度：作者把密码学里的时间锁谜题（Time-Lock Puzzle, TLP）搬进来。TLP 能把一条消息「寄往未来」——快速生成一个谜题，其解 \(s\) 必须经过约 \(t\) 步串行计算才能解开，任何用时显著少于 \(t\) 的对手（哪怕并行）都拿不到 \(s\)。这正好对应「LLM 愿意花 \(t\) 步算、过滤器花不起」的算力鸿沟。

    核心 idea：用时间锁谜题把有害指令「锁」进一段看起来人畜无害的 prompt 里——LLM 算得起、能解锁并执行有害指令；过滤器算不起，连这条 prompt 和真正善意的 prompt 都区分不开。于是过滤的不可能性不再是「攻击者比防御者聪明」，而是「防御者算力不够」这一可证伪的密码学假设的直接推论。

    方法详解¶

    整体框架¶

    这是一篇理论论文，「方法」就是一套构造性证明：作者要证明过滤不可能，只需构造出至少一个无法被过滤的 LLM 即可（因为外部过滤器必须对所有 LLM 都奏效，找到一个反例就推翻了普适性）。整套机器围绕一个目标运转：造一个对抗 prompt 生成器 \(G'\) 和一个 LLM \(M'\)，使得 \(G'\) 产出的 prompt \(z\) 同时满足——（1）喂给 \(M'\) 能诱发有害行为；（2）对任何跑得比 \(M'\) 快得多的过滤器，\(z\) 和善意生成器 \(G\) 产出的 prompt 计算不可区分。

    整个构造由三个零件咬合而成。先有一个伪随机时间锁谜题（PRTLP），它既保留了 TLP「快算者能解、慢算者解不开」的算力门槛，又被改造得「在慢算者眼里和纯随机数没区别」。再有一个可恢复随机性采样（RRS），它能模仿善意生成器 \(G\) 的输出分布、但把生成时用的随机数藏进输出里、事后还能精确捞回来。最后把两者串起来——把有害指令加密后塞进 PRTLP，用这串「看似随机」的比特当作 RRS 的随机种子去采样出一条「看似善意」的 prompt。LLM 顺着 RRS 倒推出种子、解开时间锁、读出有害指令并执行；过滤器因为算力不够，连种子是真随机还是 PRTLP 都判断不了。

    输出过滤的不可能性（定理 2）和缓解过滤的不可能性（定理 3）复用同一套思路，只是把「锁住的对象」从输入换成输出、把对手从「拒绝型过滤器」换成「修改型过滤器 + 水印」，结论甚至更强：即便允许输出过滤器跑得比 LLM 还久，也照样不可能。

    关键设计¶

    1. 计算不对称建模：把「安全算力 < 能力算力」写成定理的前提

    论文最关键的一步不是技术、而是把现实约束诚实地写进模型。它假设输入过滤器的运行时间显著小于 LLM 的运行时间 \(t\)（具体量化成 \(t^\epsilon\) vs \(t\)，\(\epsilon\in(0,1)\)）；同时为了排除「过滤器一律拒绝」这种平凡解，要求过滤器必须以高概率放行善意生成器 \(G\) 产出的 prompt，且 \(G\) 的分布是高熵的（善意 prompt 有很多、不是低熵的几条）。这套设定的针对性极强：它正是当前部署现状（12B 护栏守护千亿级模型）的抽象。定理 1 的结论——「存在 LLM \(M'\) 和对抗生成器 \(G'\)（运行时间与 \(G\) 相当），使得在时间锁谜题存在的假设下，没有显著快于 \(M'\) 的输入过滤器能区分 \(G\) 和 \(G'\) 的输出」——之所以有冲击力，正是因为前提抓住了真实世界的瓶颈，而不是构造一个脱离现实的极端反例。

    2. 伪随机时间锁谜题（PRTLP）：让「门槛」同时变成「隐身衣」

    普通时间锁谜题只保证「慢算者解不开解 \(s\)」，但谜题本身长得不随机（比如 RSW 谜题 \(\mathrm{PUZZLE}=(r,n)\) 里 \(n=pq\) 是两个大素数之积，一眼能认出来）。光「解不开」不够——过滤器只要发现 prompt 里嵌了个 RSA 模数就能起疑并拒绝。论文需要的是更强的性质：谜题对慢算者和纯随机数不可区分。作者基于 RSW 的重复平方函数 \(f(n,r)=r^{(2^t)} \bmod n\)（在不知道 \(n=pq\) 分解这个陷门时，算它需要约 \(t\) 步且无法并行；知道陷门则可先算 \(e=2^t \bmod \phi(n)\) 走捷径）构造 PRTLP，再叠上一串密码学技巧把它「漂白」成伪随机：用两两独立哈希 \(h\) 把 \(n\) 映射到大小约 \(\epsilon^2 S\) 的范围，由剩余哈希引理保证 \((h, h(n))\) 与均匀分布 \(\epsilon\)-接近；\(r\) 本就能表示成随机比特串；最后对「中等难度但未必随机」的 \(f\) 输出用 Goldreich–Levin 硬核比特做最后一道伪随机化。于是整个谜题 \(x=(h,h(n),r)\) 对慢算者就是一串均匀随机比特——这就是「把有害内容藏在明面上」却让过滤器看不见的隐身衣。LLM 解锁时需要从 \((h,h(n))\) 反推 \(n\)，因哈希是压缩的会有多个原像，LLM 枚举所有可能即可。

    3. 可恢复随机性采样（RRS）：模仿善意分布、又能把种子原样捞回

    PRTLP 给了一串「看似随机」的比特，但还需要把它变成一条「看似善意」的 prompt，并且 LLM 事后要能从这条 prompt 倒推出原始比特（才能解锁谜题）。难点在于一般的自回归采样是有损的：若 \(G\) 以概率 \(3/4\) 采某 token，需要 2 比特随机数，但看到结果 token 后无法判断当初用的是哪一种随机数，种子就找不回来了。RRS 由一对算法 \(\mathrm{Samp}_G(R)\to z\) 和 \(\mathrm{RecoverRand}_G(z)\to R\) 组成，\(\mathrm{Samp}_G\) 采出的分布与 \(G\) 完全一致、但用随机数的方式特殊到能被 \(\mathrm{RecoverRand}_G\) 精确还原。核心机制是维护「残余随机性」：以二元 token 为例，若某步 \(G\) 输出概率 \(p_i\)、当前用 \([k]\) 上的值 \(q\) 决定 token（\(q/k<p_i\) 则取 1，否则取 0），那么采完这一步后并没把随机数「用尽」，而是把剩下约 \(\log_2(p_i k)\) 比特的信息保留下来（更新 \(k\leftarrow k-\lfloor p_i k\rfloor\)），喂给下一个 token 继续用，精度不够时再从 \(R\) 拼接新比特。这样「所有随机性最终都被用上」，恢复端用一对上下界比特串 \(a,b\) 夹逼就能逐位还原 \(R\)。这套设计直接借鉴自水印文献（如 Christ et al. 2023）——把模型采样随机数嵌成可追溯标记的思路，被反过来用于「让有害种子可被 LLM 找回」。

    4. 三个不可能性定理：从输入、输出到缓解层层加码

    把上面三个零件按 \(G'(\mathrm{HARM})\)：生成 PRTLP → 用 \(\mathrm{SOLUTION}\) 加密有害指令成伪随机密文 → 拼成种子 \(R\) → \(z\leftarrow \mathrm{Samp}_G(R)\) 串起来，再让 \(M'(z)\)：恢复 \(R\) → 解出谜题 \(\mathrm{SOLUTION}\) → 解密拿到 \(\mathrm{HARM}\) → 成功则返回 \(M(\mathrm{HARM})\)、否则返回 \(M(z)\)，立刻得到定理 1（输入过滤不可能）。加密方案还自带「解密是否成功」的检测，使得 \(z\) 真来自 \(G\) 时几乎不会误触发有害模式（误报率极低）。定理 2（输出过滤不可能） 把锁住的对象换成输出，结论更强：存在 LLM \(M'\) 和有害度度量 \(H'\)，使得即便输出过滤器比 LLM 跑得还久也无法把 \(M'(m)\) 的有害输出和正常输出区分开——这意味着任何黑盒外部机制在最坏情况下都失效；且它不需要攻击者与模型合谋或共享密钥（区别于 Glukhov et al. 2024 依赖共享秘密或不可判定性的构造）。定理 3（缓解过滤不可能） 进一步放宽到允许过滤器修改 prompt：作者揭示它与水印安全性的对偶——若存在一个对编辑类 \(E\) 鲁棒的水印方案，就能构造出经过该类编辑型缓解过滤后仍诱发有害输出的 \(G'\) 和 \(M'\)。三个定理共同表明：拒绝、强算力、修改，三条路都被密码学障碍堵死。

    实验关键数据¶

    实验目的不是刷 SOTA，而是验证理论建模的现实相关性——真实部署的轻量护栏确实会被绕过，且按理论思路（时间锁式的「先解码后回答」攻击）能进一步抬高绕过率。

    主实验：真实护栏的绕过率¶

    在 JailbreakBench 的 1,097 条越狱 prompt 上，测两个真实护栏（Llama Guard 2 8B、ShieldGemma 2B）守护三种规模 LLM 的表现。

    模型 过滤器 输入过滤绕过率 输出过滤绕过率
    Llama 3.2 3B Llama Guard 34.37% 58.89%
    Llama 3.2 3B ShieldGemma 79.49% 83.49%
    Qwen 7B Llama Guard 34.37% 61.27%
    Qwen 7B ShieldGemma 79.49% 85.89%
    Mistral 24B Llama Guard 34.37% 67.37%
    Mistral 24B ShieldGemma 79.49% 89.91%

    可见相当比例的越狱 prompt 同时穿透输入和输出两道过滤，呈现「双重脆弱」——既绕过外部护栏、又攻破模型自身对齐。

    消融分析：加密如何抬高绕过率¶

    基于 Fairoze et al. (2025) 模拟「定时释放攻击」——先让模型解码加密文本、再回答解密后的内容，等于把有害 prompt 藏在一层计算之下。

    Llama Guard 34.37% 66.18% 88.06% 81.40% 81.49% 78.40%
    ShieldGemma 79.49% 78.40% 91.89% 87.15% 91.98% 87.97%

    关键发现¶

    • 加密一致地抬高输入绕过率：Llama Guard 从 34.37% 一路升到 Caesar 加密下的 88.06%，印证「利用过滤器与模型间的算力不对称、把有害内容藏在一点计算之下」确实奏效。
    • 前沿对齐模型也不免疫：用 Caesar（shift-3）定时释放攻击测 Gemini 2.5 Flash 这种内嵌对齐的前沿模型，加密版越狱成功率高于直接越狱——说明嵌在模型内部的对齐也挡不住时间锁式隐藏。
    • 理论与实践对得上：实验中观察到的「双重脆弱」正是定理 1、2 预测的——外部过滤在算力不对称下无法兜底。

    亮点与洞察¶

    • 把工程直觉证成定理：「安全算力远小于能力算力」人人都知道，但作者第一个把它写成密码学假设下的不可能性结果，让「外挂护栏不够」从经验抱怨升级为可证伪命题。
    • 时间锁谜题的妙用：TLP 本是「把消息寄往未来」的工具，被反向用作「算力鸿沟」的数学化身——LLM 是「未来的读者」、过滤器是「等不起的对手」，这个类比贴切到几乎是为对齐问题量身定做。
    • 三个「理想越狱」性质首次同时满足：有害、可证明与善意 prompt 不可区分、且无需攻击者与模型合谋——此前工作总要牺牲其中之一，本文在密码学假设下一次集齐。
    • 水印与缓解过滤的对偶：把「修改型过滤不可能」归约到「水印安全性」，揭示了攻防两个看似无关领域的深层联系，这个视角可迁移到其他「编辑鲁棒性」问题。
    • 政策含义直白且重要：既然黑盒过滤在最坏情况下注定失败，监管/审计机构就必须拿到模型权重等内部信息——这给「AI Act 该要求什么」提供了技术依据。

    局限与展望¶

    • 是最坏情况、存在性结果：定理证明的是「存在无法被过滤的 LLM」，而非「所有实际部署的 LLM 都无法过滤」。现实中的 GPT/Gemini 未必内嵌了这种时间锁解锁模式，结论是「过滤不能给出普适保证」，不等于「现有过滤毫无用处」。
    • 依赖密码学假设：所有不可能性都建立在时间锁谜题/单向函数存在之上（RSW 基于 RSA、新构造基于 LWE）。若这些假设被证伪（如量子算法破 RSA），相应构造会失效——不过 LWE 版本被认为后量子安全。
    • \(M'\) 的有害模式是「人造」的：构造里的 \(M'\) 会进入一个特殊模式去恢复随机数、解谜、执行隐藏指令，这种行为是刻意设计的。作者引用近期工作（如模型按「训练 vs 部署」条件切换行为）说明类似的上下文相关有害模式在现实模型中可能自发出现，但承认实验并未直接实例化该构造。
    • 实验规模小：作者自述是 small-scale 实验，用的是微调过的「会回答有害问题」的模型，护栏也只测了两款，离「证明前沿生产系统普遍可破」还有距离。

    相关工作与启发¶

    • vs Yuan et al. (2024)：他们纯经验地展示用 Caesar/Morse/ASCII 全程密文对话能越狱，并据此主张把密文数据加进安全训练。本文给出的是形式化不可能性——证明在密码学假设下，过滤式对齐的障碍是计算困难性，单靠更好的训练数据无法克服；且本文用时间锁谜题让模型先解码再以自然语言回答，设定不同。
    • vs Glukhov et al. (2024)：两者都研究「有害性只对下游用户显现」时的检测障碍，但 Glukhov 的反例依赖不可判定性或模型与用户共享秘密；本文的时间锁构造无需共享密钥或合谋——任何愿意花足够计算的下游用户都能解锁，而更快的输出过滤器解不开。Glukhov 的 Mosaic prompt 把有害请求拆成多条善意子 prompt，本文则把有害内容用时间锁隐写整体藏进单个善意对象，并在最坏情况下排除了句法过滤。

    • 启发：本文最可迁移的是「把现实资源约束（算力不对称）形式化为密码学假设，再推出不可能性」这一范式——可用于分析水印、内容溯源、AI 审计等一切「弱防御者守强生成器」的场景；其「外部黑盒不够、必须触及内部」的结论也可推广到模型审计与监管设计。
